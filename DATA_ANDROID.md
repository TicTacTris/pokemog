# Android Data

Regenerate from the project root with `node scripts/prepare-android-data.mjs`.
This requires Node and the installed TypeScript development dependency. Only
generation uses networking; the Android repository reads packaged assets offline.
All downloads use PvPoke commit `04ee0835e80f30c45376415725c0039cbdd12c5e`.
The script uses current bundled base stats and verifies them and the CPM table
against that pin. It does not update any web data or configuration.

## Evolution Metadata

`pokemon.json` preserves upstream `family.evolutions` ordering and regional
branches. Normal/shadow counterparts are explicit `shadowId`/`normalId` links,
not evolution edges. Shadow-to-normal source edges are mapped to shadow targets
only when the target exists; otherwise they are omitted and reported. No form
transformations, reverse evolutions, purification, or inferred family-wide links
are added. Evolution availability, event restrictions, items, gender, and other
in-game requirements are not modeled. Upstream omissions remain omissions (for
example, Exeggcute lists only ordinary Exeggutor).

Pinned-source repairs: Rockruff's `lycranroc_dusk` typo is corrected to
`lycanroc_dusk`. Missing targets `kleavor_shadow`, `farigiraf_shadow`, and
`wyrdeer_shadow` are omitted rather than fabricated or converted to normal forms.
All other unresolved edges and all cycles fail generation.

`evolution-metadata.json` distinguishes absent family metadata from a family
record with no forward edges, and records corrections and omitted/remapped shadow
edges. Both missing metadata and terminal nodes expose an empty `evolutions` list.
The Kotlin loader now reads that report into `Pokemon.hasEvolutionData`: a record
must not be listed as missing and must have forward edges or explicit terminal
metadata. Synthetic records default to unknown. Scan calculation-equivalence
requires known metadata throughout both normal and linked Shadow graphs; empty
edges alone never establish terminal status. No claim of a complete current-game
evolution graph is made. No generated dataset or shared web data was changed for 0.8.1.
PvPoke's MIT license is included in assets and test resources.

## Calculations And Tests

`Calculations` copies and validates 101 multipliers for levels 1 through 51.
`stats` preserves unrounded effective attack/defense, CP and HP floors, and fixed
Shedinja HP. Shadow damage multipliers are not applied, matching the web engine.
`rankIVs` uses all 4096 spreads, the highest eligible half-level, deterministic IV
ordering, and shared competition ranks. `inferLevels` searches base levels 1 to
50 inclusive; active buddy adds one only when calculating observed stats.
Invalid inputs throw `IllegalArgumentException`. Kotlin integer types exclude
fractional/non-finite IVs and displayed stats by construction. CP exceeding
`Int.MAX_VALUE` is rejected instead of silently overflowing; this only affects
synthetic base stats far beyond the dataset.

TSV fixtures are generated by transpiling and executing the actual TypeScript
engine with pinned CPMs. They cover effective stats, every ranking row for ten
cases (including ties, partial/empty rankings, plateaus, and level 51), and known-IV
inference using TypeScript `stats` as the oracle. Tests use JUnit4 and standard JVM
resource reading, with no Android JSON dependency. CP, HP, order, levels and ranks
are exact assertions; floating-point battle stats allow a small cross-runtime
rounding tolerance. Run the parent project's Android unit-test task when its
Gradle and SDK environment is available.

## Cropped Image Fixtures

The five PNGs in `src/lib/fixtures/` and the copied
`android/app/src/androidTest/assets/s23-ultra-appraisal.png` retain only Pokemon GO
appraisal bars and labels. The `appraisal-*.json` pixel fixtures in
`android/app/src/test/resources/` are derived regression representations of those
crops, including resized variants. Full private screenshots and diagnostic exports
are not test inputs to publish. Review both visible pixels and metadata before
adding or replacing any image; remove trainer details, locations, dates and other
private screen content from the public fixture, not from the user's original file.

These crops contain third-party copyrighted game UI. Their use as regression
fixtures is not a copyright license grant: neither PokeMog's MIT license nor
