# Local Release Signing

The dedicated release key is separate from all Android debug keys. Never commit
it, base64-encode it into source, print passwords, attach it to a release, or put
it in a build artifact. These workflows do not require GitHub signing secrets.

```sh
# Once only; refuses to replace an existing signing directory:
node scripts/release-signing.mjs init
```

The script creates `$HOME/.local/share/pokemog-signing/` with mode `0700` and
`pokemog-release.p12` and `secrets.json` with mode `0600`, outside the project.
`secrets.json` holds `storePassword`, `keyPassword`, `alias`, and `keystorePath`.
Passwords use 48 cryptographically random bytes generated by Node; PKCS12 uses
the same strong password for the key and store. Keytool generates RSA-4096,
SHA256withRSA, validity 10,000 days, alias `pokemog-release`.

Passwords reach keytool only through `-storepass:env POKEMOG_STORE_PASSWORD`
and `-keypass:env POKEMOG_KEY_PASSWORD`, never literal command arguments.
The local loader checks ownership/permissions and passes signing values only
to child keytool/Gradle processes. Run this only on a trusted workstation:
the build and local account can access its environment. Do not use Gradle debug
logging, build scans, or credential-dumping diagnostics while signing.

Gradle accepts these variables together:

- `POKEMOG_KEYSTORE_FILE`
- `POKEMOG_KEYSTORE_PASSWORD`
- `POKEMOG_KEY_ALIAS`
- `POKEMOG_KEY_PASSWORD`

Partial configuration fails. No configuration means unsigned release builds are
allowed for CI. `:app:verifyReleaseSigning` fails without all credentials;
the packaging script additionally verifies the actual APK signature against the
local key fingerprint. Never configure release to fall back to a debug key.

## Backup And Recovery

Back up the **entire signing directory** to encrypted offline storage with
restricted access, separate from source backups. The local directory is the
active key store, not itself a backup. Verify recovery with `keytool` and compare
the public certificate SHA-256 before trusting the backup. Do not delete or
rotate the key casually: existing Android installations require a compatible
signer for updates. No backup or remote secret upload is performed automatically.

```sh
node scripts/release-signing.mjs certificate
```

This prints only the public certificate SHA-256. Publish that fingerprint with
the APK checksums over a trusted channel. An APK hash detects byte changes, not
the trustworthiness of its publisher.

## Install Identity

Release: `dev.pokemog.android`, version `0.10.0`, code `12`, non-debuggable.
New debug builds: `dev.pokemog.android.debug`, installed separately. Existing
debug keys are untouched. An older debug build using `dev.pokemog.android`
conflicts with the production key and must be uninstalled before installing this
release; uninstalling loses its local data/settings. Stop capture first. A new
dedicated release key cannot update an old debug-signed production package in
place. Compiling instrumentation is not a successful device test.
